# 2026-10-23

## 已实施：OTA 层内再分组 + 层间延时改 10 秒

需求：每层下发时先判断该层设备数，超过 3 台就按 3 台一组切分（不足 3 台也单独成组），
一组完成才发下一组，本层所有组完成才进入下一层；`LevelStabilizeSeconds` 300 → 10。

用户决策：① 超时按**每小组独立 10 分钟**（不是整层总额）；② **组间不等待**，立即发下一组。

改动：
- `appsettings.json`：`LevelStabilizeSeconds` 300→**10**，新增 `LevelGroupSize: 3`
- `OtaBatchState`：新增 `CurrentGroupIndex`（1 起，进新层重置为 1）
- `OtaUpgradeService`：
  - 新增 `_levelGroupSize`（配置 `OtaUpgrade:LevelGroupSize`，≤0 抛异常）
  - 新增 `BuildLevelGroupsAsync`：`targets ∩ 层清单` 的**全量快照**按 DeviceId 排序后
    `.Chunk(_levelGroupSize)`
  - 新增 `AdvanceGroupAsync`：组号+1、状态回 `Pending`、清 deadline，组间不等待
  - `StartLevelAsync` 改为只下发**当前组**；`groups.Count == 0` 时空层快跳；
    `CurrentGroupIndex > groups.Count` 时 `CompleteLevelAsync`（层完成 → 10 秒延时）
  - `VerifyLevelAsync` 改为按组判定：组成员在 targets 里**都不再是 `pending`** 即本组完成
  - `AdvanceLevelAsync` 重置 `CurrentGroupIndex = 1`
  - 删除 `IsUpgraded`（组判定改为"非 pending"，不再需要）
- `CODEBUDDY.md`：分组规则、组完成判定、超时按组、配置段全部同步。构建 0 错误。

**关键坑（已避开）**：分组必须用「targets ∩ 层清单」的**全量快照**，
不能用"仍待升级的设备"切——每完成一台它就从名单消失，组边界会漂移、组号指向错误设备。

**日志标识**：`OTA 第 {Level} 层第 {GroupIndex}/{GroupCount} 组已下发`，
排查分组问题时按这个关键字找。

## 追加：第 1 层超时 20 分钟，超时即判定 OTA 失败并取消后续

需求：第 1 层超时改为 20 分钟；一旦触发就表示 OTA 升级失败，直接取消后续操作。

**为什么必须加新配置**：现有公式 `Base + (层-1)×Increment` 只能表达"递增"或"全部相同"，
**表达不了"第 1 层比后面长"**（L1=20、L2=10 需要负增量）。所以新增
`OtaUpgrade:FirstLevelTimeoutMinutes`（默认 0 = 沿用 Base），`LevelTimeout()` 里
`level <= 1` 时优先用它。当前配 20，其余层仍 10。

**取消后续的实现**：`VerifyLevelAsync` 超时分支新增判断
`firstLevelTimeout = _abortOnFirstLevelTimeout && level <= 1`（配置
`AbortOnFirstLevelTimeout` 默认 true）→ 直接 `FinishBatchAsync`，
**不进下一层、不进补发、不广播 CanRestart**。
批次状态仍是 `finished`（`OtaBatchStatuses` 只有 active/finished，未新增 failed），
失败语义通过 reason 日志 + targets 全 failed + `ota_upgrade_failed` 故障体现。

启动日志已补 `FirstLevelTimeoutMinutes / LevelGroupSize / AbortOnFirstLevelTimeout /
SendCanRestartOnComplete` 四个参数，方便核对生效值。构建 0 错误。

## 追加：重启前等待剩余设备（restarting 阶段，20 分钟）

需求：收尾时若还有未升级的设备，**不要直接重启**；给 20 分钟窗口，
窗口内全部完成就立即重启，超时没完成也照常重启。

实现：
- 新增 `OtaLevelStatuses.Restarting` + `OtaBatchState.RestartDeadlineUtc`
- 配置 `OtaUpgrade:RestartWaitTimeoutMinutes`（默认 20，当前 20）
- 新增 `EnterRestartPhaseAsync`（补发结束后调用，替代原先直接 FinishBatchAsync）：
  - 全部 upgraded → 立即 FinishBatch（内部广播重启）
  - `upgraded == 0` → 直接 FinishBatch（重启无意义，内部会跳过广播）
  - 有未完成且 `upgraded > 0` → 进 Restarting，记 deadline
- 新增 `VerifyRestartAsync`（每秒轮询）：窗口内全补齐 → 立即重启；到期 → 照常重启
- `FinalizeDispatchAsync` 的"无需补发"分支也改走 `EnterRestartPhaseAsync`
- `FinishBatchAsync` 新增 `allowRestart` 参数（默认 true），第 1 层超时中止时传 false，
  并清 `RestartDeadlineUtc`

**关键坑**：Restarting 阶段**不能**把 pending 标成 skipped，
否则窗口内上报 OTACP 的设备会被当成从未完成、统计也不准。
`pending → skipped` 的统一转换仍留在 `FinishBatchAsync` 开头。

**副作用（预期内）**：等待期间该架仍持有 active 批次，新 OTA 指令会被
`RejectConcurrentBatchPerRack` 拒绝，最长 20 分钟。构建 0 错误。

## 追加：第 2 层强制逐台下发

需求：第 2 层 OTA 必须一台一组。

实现：新增配置 `OtaUpgrade:SecondLevelGroupSize`（默认 1），
`BuildLevelGroupsAsync` 里 `state.CurrentLevel == 2` 时用它，其余层仍用 `LevelGroupSize`。
原因：第 2 层节点全部经根节点中继，并发下载会压垮根节点转发。

**注意**：用户手动把 `LevelGroupSize` 从 3 调成了 **2**，我保留了用户的值（没有覆盖回 3）。
以后改这个配置前先看 appsettings 现值，别按文档里的"默认 3"覆盖。

超时按组独立计时，所以第 2 层 4 台 = 4 组 = 最坏 40 分钟。构建 0 错误。
