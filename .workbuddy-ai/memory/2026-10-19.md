## 排障：手工 XADD 的 ota 指令服务读不到（只答疑，未改代码）

用户在 Redis workbench 用 EVAL + XADD 写 `lgw:cmd:queue`，字段名写成了 `payload`。
`CommandRepository.ReadAsync` 第 91 行硬编码取 `data` 字段，取不到就 `continue` 整条跳过 →
消息被消费组读走但解析不出命令、也不会 XACK，会一直挂在 PEL 里。
正确写法：字段名必须是 `data`（AGENTS.md 早有约定）。废消息用 XRANGE 找 ID 后 XDEL 删除，不要 FLUSHDB。

## 已实现：上线报文新增 MeshLevel，维护 OTA 分层清单

需求：上线主题 `device/public/up_line` 新增 `Data.MeshLevel`，上线时把设备写入
`lgw:ota:{AgingNumber}:{MeshLevel}`（List）。例：`lgw:ota:88:1`。

实现要点（三处配套维护，缺一清单就失真）：
1. 写入该键前先移除键内同设备旧元素 —— 复用 DeviceRepository 已有的私有
   `RemoveDeviceFromOnlineListAsync`（它按 JSON 里的 id 匹配再 LREM）。
2. 换架 / 换层级时按 `runtime.MeshLevel`（新字段）定位旧分组并移除 ——
   否则同一设备会同时留在 `lgw:ota:88:1` 和 `lgw:ota:88:2` 两个清单里。
3. `DeviceOfflineHandler` 离线时移除 —— 否则清单残留已离线节点。

其它决策：
- 元素格式与其它在线列表同构：`{"id","type","AgingNumber","MeshLevel"}`，便于 OTA 直接取用。
- 老固件没有 MeshLevel → 只告警跳过，不写入（不阻断上线流程）。
- 键不设过期（与在线列表一致，由上下线生命周期维护）。

## 已实现：OTA 重构为「按 Mesh 分层逐级升级」（取代旧方案）

旧方案（整架一次性下发 + 全下载完广播 CanRestart + OTACP 上报计数）**已整体移除**。
新方案（用户口头需求 + 5 轮确认后定稿）：

- **单设备 ota 直接普通命令转发**，不建批次、不分层、不比版本（无 mesh 依赖）。
- **多设备由 OtaUpgradeService 接管**：`DeviceInfos[0]` 的 runtime.AgingNumber 为架号；
  命令流整条 `MarkCompleted`（消息写明已接管）并 ACK，避免 Stream Entry 挂几十分钟。
  命令状态用新增的 `CommandRepository.MarkCompletedAsync`（原仓库只有 MarkFailed/MarkTimedOut）。
- **名单 = DeviceInfos 全集**（`...:targets` Hash，deviceId→pending/upgraded/failed/skipped），
  分母即 DeviceInfos.Count；下发对象 = 名单中仍 pending **∩** `lgw:ota:{架}:{层}` 清单（用户选"取交集"口径）。
- **从 Mesh 层 1（根节点）开始逐层向上**，层内并行、层间串行；靠 `runtime.FirewareVersion`
  变化确认该层重启成功（旧版本为空时以"变为非空"判定）。
- **层间加 mesh 稳定等待**（LevelStabilizeSeconds 默认 60s）：上层重启会让下层短暂掉线，
  不等待的话取交集时会把它们误判成"不在名单里"而 skipped。这是我主动提的，用户采纳。
- 超时 = BaseTimeoutMinutes + (L-1)×IncrementMinutes；超时设备标 failed + fault 后**跳层继续**
  （用户选；`AbortOnLevelTimeout=true` 可改中止）。连续 2 层空或超 MaxMeshLevel 结束。

### 追加修正：节点重启后 MeshLevel 会变化（用户实测反馈）

- **重复下发防护已有**：`StartLevelAsync` 只下发 targets 中 `pending`（+ 现在的 `skipped`）状态的设备，
  已 upgraded 的设备即使因层数上移进入更高层清单也不会被二次下发。
- **新增 skipped 补发**：过滤条件放宽为 pending + skipped（failed 不重试，避免重复刷机）。
  下发前先 `SetTargetStatus(pending)`，避免 skipped 设备在多个层被重复下发；
  发布失败/离线则退回 skipped 留给后续层重试。
- **新增空层快跳**：原"连续 2 层空即结束"会漏掉层数上移的设备（它跑到 L4，而 L2/L3 空 → 提前结束 → 被标 skipped）。
  改为：空层**不等 mesh 稳定期**直接进上一层；结束条件只剩两个——名单中无 pending/skipped，或层数超 MaxMeshLevel。
  `EmptyLevelStopCount` 配置与 `state.EmptyLevelCount` 字段已删除。

关键坑（后续别踩）：
- `runtime` 的版本号字段是 **FirewareVersion**（项目拼写），且 DeviceNode 模型没有该属性，
  `GetAsync()` 读不出来 → 必须走 `DeviceRepository.GetFirmwareVersionAsync` 单字段取。
- RedisHelper 原本没有 HashGetAllAsync → 为读 targets 新增了该方法。
- 结束时会把仍是 pending 的设备标 skipped（从未被下发）。
