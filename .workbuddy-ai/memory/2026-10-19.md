## 排障：手工 XADD 的 ota 指令服务读不到（只答疑，未改代码）

用户在 Redis workbench 用 EVAL + XADD 写 `lgw:cmd:queue`，字段名写成了 `payload`。
`CommandRepository.ReadAsync` 第 91 行硬编码取 `data` 字段，取不到就 `continue` 整条跳过 →
消息被消费组读走但解析不出命令、也不会 XACK，会一直挂在 PEL 里。
正确写法：字段名必须是 `data`（AGENTS.md 早有约定）。废消息用 XRANGE 找 ID 后 XDEL 删除，不要 FLUSHDB。

## 已实现：上线报文新增 MeshLevel，维护 OTA 分层清单

需求：上线主题 `device/public/up_line` 新增 `Data.MeshLevel`，上线时把设备写入
`lgw:ota:{AgingNumber}:{MeshLevel}`（List）。例：`lgw:ota:88:1`。

实现要点（三处配套维护，缺一清单就失真）：
1. 写入该键前先移除键内同设备旧元素 —— 复用 DeviceRepository 已有的私有
   `RemoveDeviceFromOnlineListAsync`（它按 JSON 里的 id 匹配再 LREM）。
2. 换架 / 换层级时按 `runtime.MeshLevel`（新字段）定位旧分组并移除 ——
   否则同一设备会同时留在 `lgw:ota:88:1` 和 `lgw:ota:88:2` 两个清单里。
3. `DeviceOfflineHandler` 离线时移除 —— 否则清单残留已离线节点。

其它决策：
- 元素格式与其它在线列表同构：`{"id","type","AgingNumber","MeshLevel"}`，便于 OTA 直接取用。
- 老固件没有 MeshLevel → 只告警跳过，不写入（不阻断上线流程）。
- 键不设过期（与在线列表一致，由上下线生命周期维护）。

`DeviceRepository.cs`（SaveOtaMeshLevelAsync / RemoveOtaMeshLevelAsync / SaveOnlineAsync 加 meshLevel 参数写 runtime）、
`Handlers/DeviceOnlineHandler.cs`、`Handlers/DeviceOfflineHandler.cs`、`AGENTS.md`。构建 0 错误，未真机验证。
