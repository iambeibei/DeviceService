## 老化数据上传链路 Seq 去重分析（只分析，未改代码）

用户问：2 个老化架群控同时上报、同一秒内出现 seq 相同但 pn 不同的数据，会不会被误去重/覆盖。

### 两条链路的结论

**1) 老化采样数据 `device/{id}/data/aging` —— 不存在任何 Seq 判重**
- 入口 `AgingDataHandler.HandleAsync`：`SaveAgingDataAsync` + 同步 HTTP POST。
- Seq 只作为普通字段写入，不参与判重：
  - `lgw:device:{id}:aging:{pn}:latest` Hash：维度 **(deviceId, PN)**，同 key 覆盖（最新值语义）。
  - `lgw:device:{id}:aging:{pn}:history` Stream：`RedisHelper.StreamAddAsync` 不传 messageId →
    Redis 自动生成 `*`，**同 Seq 全部追加，永不覆盖**。
- `DeviceRepository.MarkSeenAsync` 只无条件写 `LastMessageSeq`，**没有单调过滤**，不会因 Seq 回退丢数据。
- 判重维度含 deviceId 和 PN，且两个架 deviceId 不同 → **同 Seq 不同 PN 互不影响，不会丢数据** ✅

**2) TaskCP 阶段完成 `device/{id}/event/TaskCP` —— 存在 Seq 单调判重**
- `GroupControlService.RecordTaskCompletionAsync`：
  `GetLastTaskSeqAsync(agingNumber, deviceId)`，`if (lastSeq.HasValue && seq <= lastSeq.Value) return;`
- 判重维度 = **(AgingNumber, DeviceId)**，键 `lgw:group-control:{n}:taskcp:last-seq`（Hash，field=DeviceId）。
  **不含 RunSeq**，是设备级而非批次级。
- Seq 来源：报文顶层 `json["Seq"]`（`GroupControlTaskCompletionHandler`），与采样数据 Seq 同源。
- 两架同 Seq 不冲突（维度含 DeviceId）✅

### ⚠️ 发现的高风险项（未改代码，待用户决定）

1. **`taskcp:last-seq` 跨批次不重置**：无 TTL、全代码无删除/清理点（grep 确认只有
   `GetLastTaskSeqAsync`/`SetLastTaskSeqAsync` 两处使用）。若设备每批次 Seq 从头计数，
   第二批次所有 TaskCP 会被判"重复或乱序"**全部丢弃** → 阶段永不完成 → 放行永久阻塞。
   （这很可能是放行卡住的真实根因之一，值得优先排查。）
2. **判重顺序在 participants 检查之前**：Mode → lastSeq 判重 → CurrentRunSeq → participants。
   被丢弃时日志只打"忽略重复或乱序 TaskCP"，不会提示非参与设备，排查容易误判。
3. **老化数据 HTTP POST 串行阻塞全局 MQTT 通道**：`MqttMessageWorker.ExecuteAsync` 是
   单条 `await foreach` 串行循环，所有消息（含 TaskCP / 状态 / 放行回复）共用这一条循环；
   `AgingDataHandler` 里 `await DataSQLHelper.JsonHttpPostAsync(...)`（HttpClient 30s 超时）会
   卡住整个循环。两架同时高频上报会放大延迟，直接影响群控放行时效。
4. **POST 失败被静默吞掉**：`DataSQLHelper.JsonHttpPostAsync` catch 后只返回 "false: ..."，
   而 `AgingDataHandler` 里 `var rtxt = ...` 后日志行被注释掉 → **Redis 已写、平台未收到，
   且无任何日志与重试**。
5. **POST body 不带 deviceId**：`new { payload = JToken.Parse(payload) }` 只转发原始报文，
   deviceId 只在 MQTT topic 里。平台侧只能从 payload 内部解析身份；
   若平台用 Seq 做幂等/唯一键，两架同 Seq 会在平台侧互相覆盖。

### 重复写入风险

MQTT QoS>0 重投或设备重发同一条采样数据时，没有任何去重 → history Stream 会出现完全
重复条目；latest Hash 覆盖为同一条（幂等，无害）。
